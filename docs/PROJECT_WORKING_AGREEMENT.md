# 项目施工、验收与备份约定

本文件是后续版本持续执行的硬约束，不因会话切换、额度中断或机器回收而失效。

## 每个版本的完成顺序

```text
设计与实现
→ 开发期测试
→ 完整验收
→ commit + annotated tag
→ 立即 push 分支和 tag
→ 核验远端 refs 指向本地提交
→ 保存并验证 Git bundle 与源码快照
→ 对冻结提交做一次独立、稍详细的自查
→ 将高性价比不足纳入下一版本
→ 再开始下一版本设计与实现
```

开发中做过 code review 或测试，不能替代提交后的冻结版本自查。原本用于逐段讲解的位置，即使
暂时推迟面向用户的教学，也必须保留为独立复盘环节。优先处理高性价比的正确性、显存、性能、
可恢复性和证据质量问题，避免无依据的大重构。

## 中断与实时恢复

- 未完成版本绝不 reset、clean、checkout 丢弃或回退；保留半成品 dirty state；
- 每到可独立恢复的实质节点，就更新异地恢复 tar、binary patch 和 Git status；
- 完整版本保存可验证 Git bundle 和源码快照；
- GitHub 与持久资料副本是两条独立恢复链，不能只依赖瞬时工作区；
- push、备份或校验失败必须明确记录并继续重试，不能默认为已经完成；
- 不把同一磁盘上的第二个目录冒充异地备份。

## 模型与实验口径

- 正式模型为 `Qwen/Qwen3-32B` dense；
- tiny MiniGPT/Qwen3 只用于正确性、回归和 CI；
- 正式性能报告只接收真实模型和真实硬件的数据；
- 静态估算必须标记为 estimate，不能冒充 measured peak；
- 优化前先过数值一致性门禁，报告保留命令、代码版本、模型清单、原始 runs 与指标定义；
- 面试含金量来自可复现的正确性、性能归因、系统设计和多卡 Scaling，而不是仅声称模型更大。
